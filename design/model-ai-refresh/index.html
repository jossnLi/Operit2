问题现状设计对策

02

技术调研：两种接入方式到底能不能做

结论先行：五家已接入真实账号登录（OpenRouter、Kimi、Codex、xAI、Claude Code），Gemini 的个人 Google 登录通道已在 2026 年 6 月关闭。Claude 采用 Claude Code 的手动授权码，合规风险最高，只作为用户主动选择的可退路径。所有「账号登录」最终都必须能回答三个问题：凭据怎么来、额度算什么、失败怎么退。

供应商方式一 · 账号登录额度/计费可行性与依据风险与控制
OpenRouter OAuth 2.0 + PKCE，官方支持
无需注册 client，回调可用 localhost		 账户信用额度（credits） 授权后 POST /api/v1/auth/keys 换取 user-controlled key，本质是「用账号换一把属于用户的 Key」。官方文档明确 PKCE 强制。 低 与 Key 方式同源，授权失败直接退回粘贴 Key。
Kimi Kimi Code 设备码（auth.kimi.com）官方 会员额度（Kimi Code 套餐） 官方 CLI 文档给出的标准设备码流程；请求时必须完全省略 scope 参数；端点 api.kimi.com/coding/v1 同时兼容 OpenAI 与 Anthropic 协议。 中 设备 30 天未活动失效；Kimi Code 与开放平台是两套账户，Key 不可混用，页内必须写清。
Codex ChatGPT 账号 OAuth（PKCE 回环 localhost:1455 + 设备码兜底）已实现 订阅额度（5h / 周窗口） Codex CLI 公开 client id；仓内 CodexOAuth.rs 已跑通刷新与额度查询，属本项目既有能力，重构只换皮不换协议。 中 非官方客户端复用订阅，存在风控可能；保留 Platform API Key 作为备选，页内说明。

Gemini Vertex AI 项目授权（Google 账号 + 项目 + 区域）官方替代 GCP 计费 / Vertex 配额 Gemini Code Assist 个人版自 2026-06-18 起停止为 IDE 与 Gemini CLI 提供「使用 Google 登录」；且以第三方软件直接访问 Code Assist 服务违反条款。剩下可行的只有 AI Studio Key 与 Vertex（项目授权或 ADC）。 低 项目授权合规，需用户自备 GCP 项目与结算方式。
Claude Claude Code 手动授权码（platform.claude.com/oauth/code/callback）已实现 · 高风险 Claude 订阅额度 复用 Claude Code 官方 CLI 的 OAuth 端点与客户端指纹，用户在授权页复制 code#state 回贴完成换码。Anthropic 合规文档仍明确限制第三方提供 Claude.ai 登录与代路由订阅凭据，本实现仅响应用户主动选择。 高 默认不推荐，仅在对应用户主动发起时可用；保留 Console API Key / Bedrock / Vertex 作为可退路径，登录失败或账号受限时回退。

一条底线

任何「账号登录」都不得把订阅凭据转卖给第三方或代他人路由请求。因此本设计里账号方式只用于用户自己的账号、自己的额度，且始终保留 API Key 方式作为可退路径。

2.1 技术路线收口

统一授权引擎（Rust）

一个 ProviderAuthEngine，三种 flow 实现同一状态机：LoopbackFlow（Codex / OpenRouter，起本地端口收 code）、DeviceFlow（xAI / Kimi，展示码 + 轮询）、ManualCodeFlow（Claude Code，浏览器授权后回贴 code#state）。

凭据统一落 ProviderCredential{ authMode, accessToken, refreshToken, expiresAt, accountId, email, planLabel, scopes }，由 Rust 侧加密存储，UI 只读状态。

判定「当前生效」的唯一规则

每个供应商同一时间只有一个生效凭据：账号凭据有效 → 账号；否则 → Key；都没有 → 未连接。切换方式是显式动作（「切换为 API Key」），不做自动混用，避免掉额度与账单归属不清。

3.3 核心流程

流程 A · 首次接入一个供应商（以账号方式）

1

总览点卡片 → 详情。顶部「当前生效：未连接」，方式一卡片为主动作。

2

点「使用 ChatGPT 账号登录」→ 授权流程页：生成 PKCE、拉起系统浏览器、页面进入等待授权（同时提供「改用设备码」）。

3

回调成功 → 换 token → 拉账号信息（邮箱 / 档位）→ 回详情，方式一显示已连接 + 邮箱 + 档位，方式二降级为「可切换」。

4

自动同步该供应商模型（Codex 走内置 20 个固定型号）。默认全部关闭，用户在模型库显式启用。

流程 B · API Key 方式（含校验四态）

1

详情「配置 Key」→ Key 配置页，输入框 + 显示/隐藏 + 从剪贴板粘贴。

2

点「校验并保存」→ 校验中（1 次最小 chat 请求 + 1 次 list_models）。

3

成功：显示可用模型数、是否支持余额查询，回详情；失败：就地展开错误分类（Key 无效 / 区域受限 / 额度不足 / 网络）。

4

若当前是账号方式在生效，保存 Key 后需二次确认「切换为 Key 生效」——避免静默换掉正在用的额度。

流程 C · 授权失效与恢复

1

刷新失败 → 凭据标记 需重新授权：详情卡片变黄、主页「需处理」出现该供应商、相关模型标灰并注释「暂不可用」。

2

点「重新授权」→ 同一授权流程页，保留上次账号提示，成功后恢复；连续失败给出「改用 API Key」的一键出口。

交互原则

页内展开优先于弹窗：只有「删除供应商 / 切换生效方式 / 清空 Key 池」三个不可逆或影响计费的动作才二次确认；其余全部就地完成，返回即保存。

4.2 主题适配

跟随用户的主题配置

  • 主题来源：ColorScheme.fromSeed(seed: #3B82F6, DynamicSchemeVariant.tonalSpot)，暗色再用 copyWith 覆盖中性面
  • 用户开启 useCustomColors 或导入 ThemeVisualSpecV1 调色板时，强调色整体换掉，版式与层级完全不动
  • 因此设计里所有「蓝」都只出现在 primary 一个变量上，没有一处写死品牌蓝

深色下的九处具体处理

  • Codex 结环 / xAI 的 X 由黑转白（品牌 mark 的官方浅色版）
  • Gemini / Kimi / OpenRouter 的渐变在深色下保持原色相，只降一点明度
  • 开关由 iOS 绿改为 primary，避免蓝绿两套强调色打架
  • 浅色下的白底次要按钮改 surfaceContainer，防止白字消失
  • 账号头像底色改为 token（浅紫 → 暗紫），不再出现刺眼白圆
  • 警示 / 失败条用暗色 tint + 提亮文字，不用亮色块
  • 代码块用 surfaceContainerHigh，长串改 overflow-wrap 不在词中断行
  • 卡片阴影减到 35% 黑，深色下靠明度而非投影分层
  • 分割线降到 #262628，避免深色里出现灰白网格

4.4 组件语汇

基础件

  • Group / Row：分组卡 + 行（图标、标题、副标、右侧值或控件）
  • StatusStrip：供应商详情首屏三格结论（生效方式 / 型号与启用数 / 最近测试或额度）
  • MethodSwitch：账号登录 / API Key 分段切换，互斥生效
  • FoldedMethod：未选方式折成一行（状态摘要 + 动作），点按才展开配置
  • StatusPill：已连接 / 需重新授权 / 校验中 / 不可用
  • Segmented：方式切换、端点选择、筛选
  • InlinePanel：页内展开的高级项（端点、Header、Key 池）
  • KeyField：密钥输入（key 前缀 + 掩码 + eye 可见性切换）
  • Steps：授权流程三步条
  • QuotaBar：5h / 周窗口、credits 用量

语义规则

  • 开关只用于布尔设置（流式、缓存、自动同步）
  • 勾选圆点用于「启用/选中」语义（模型库），减少绿色噪音
  • 状态 pill 一律「颜色 + 文字」，不靠颜色单独表意（色觉友好）
  • 危险动作：红字 + 二次确认，且确认里写清后果（影响哪个模型）
  • 空态必须给下一步动作，不写「暂无数据」了事

4.5 图标政策（硬性）

供应商图标必须使用官方 brand mark

六家一律使用官方 logo 的矢量路径（Simple Icons / Lobe Icons 源，内联为 SVG，本地渲染，无外链）：Gemini 渐变四角星、Claude 放射花、OpenAI 结、xAI 的 X、Kimi 的 K 折角、OpenRouter 双箭头。深色模式切浅色版本（Codex / xAI 由黑转白）。不复刻、不重绘、不用字母标替代。

4.5.2 主题适配

图标底板不再写内联颜色，统一用 .itile.blue / .amber / .green / .red / .n 五个语义类，分别映射到主题的 primaryContainer、warningContainer、successContainer、errorContainer、surfaceContainerHigh。改主题种子色或切深浅色，底板与描边同步变，不需要逐页改样式。

项规则
描边颜色全部 stroke: currentColor，由外层 color 决定；只用 primary / onSurfaceVariant / outline / 语义色，不写死十六进制
图标底板五档语义类：账号与模型 blue、Key 与额度 amber、测试通过 green、清除与失效 red、诊断与高级设置 n；同一分组里最多两种，避免彩虹色
语义图标底色成功 ok、警示 warn、失败 err 用各自的 tint；失败条描边改为 err 34% 透明，不再写死 #f0cfd5
深色切换只换描边与底板颜色，图形不动；线宽在深色下保持 1.7，不因对比度提高而加粗
与品牌图标共存品牌 mark 保留官方原色（Codex / xAI 深色转白），线性图标永远跟随主题色，两者不互相取色
箭头对比度行尾 chevron 统一 onSurfaceVariant（不再用最浅的 text-4），深色下也看得见可点
输入框前缀Key 输入框左侧固定 key、右侧 eye：只表达“这是什么”和“是否可见”，不放锁形图标（锁会被误读为“已加密不可改”）
不可用状态未授权模型的勾选位改成灰底 minus（.chk.dis），不再留一个看起来能点的空圆

4.6 细节与交互反馈

项规则
行按压整行可点时给 :active 底色 --pressed（浅 4.5% 黑 / 深 5.5% 白），过渡 140ms；不改变布局，只给触觉替代

开关与分段开关滑块 180ms 曲线 cubic-bezier(.3,.9,.3,1)，开启态带 4px 主色投影；分段选中态用“抬起的卡片”隐喻（浅色白底 + 阴影，深色 #2C2D31）

等待态授权等待用 24px 旋转环 + 已等待计时；超过 90 秒才把“改用设备码”提升为主入口，避免一开始就分散注意力
